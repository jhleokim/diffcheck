# 전문가 관점 교차검토 기록 (2026-09-11)

설계 초안(`DESIGN-DRAFT.md`)을 세 관점에서 검토하고, 서로 어긋나는 지점을 맞붙여 본 기록이다.

- **신탁사 계약 실무 관점** — 수탁자가 무엇을 책임지는가
- **대주(은행·증권) 대출약정 관점** — 대출약정서와 신탁계약서가 어긋나는 지점
- **시행사 대표 관점** — 우리가 만든 도구가 상대편에게 어떻게 보이는가

이 문서를 남기는 이유는 두 가지다. **첫째, 검토 의견을 그대로 반영하지 않았다.** 확인 가능한
것만 실물 대조로 검증하고 통과한 것만 초안에 넣었다. 둘째, **기각한 의견과 갈린 의견이
나중에 다시 올라올 것**이므로 왜 그랬는지 남겨둔다.

---

## 0. 검증 방법

검토 의견 중 "실물이 이렇다"는 주장은 전부 **실제 파일에 직접 대조**했다.
대조 대상은 `experiments/cross-document/ktrust_land.txt` (한국토지신탁 「토지신탁계약서(관리형)」
25p·35조, 금감원 신고 약관 공시본)이다.

검증되지 않은 주장은 초안에 넣지 않고 §13.1 「실무에서 확인해주셔야 할 것」으로 내렸다.
**관행을 지어내는 것이 이 작업에서 가장 위험한 실패 양식**이기 때문이다.

## 1. 실물로 확인된 것 → 초안에 반영함

### 1.1 본문이 특약에 위임한 자리가 5곳 있다 ✔ 확인

`신탁특약` 13곳 중 본문이 판단을 특약에 넘긴 자리:

| 본문 | 위임 내용 |
|---|---|
| 제3조②5호 · ④4호 | "그 밖에 신탁특약에서 정하는 업무" |
| 제15조② | "신탁특약에서 정한 조건에 따라 분양" |
| 제28조③ | 귀속권리자 |
| **제29조①단서** | 하자 책임·세금·소송 금액·민원처리 비용의 지급 유보 |

제29조①단서가 **유보금의 유일한 법적 근거**다. 특약이 이 자리에 침묵하면 근거가 사라진다.

**그런데 지금 모드 E는 이걸 "특약이 안 건드림 → 접기"로 지운다.** 합성 특약에서도
제3조·제28조·제29조가 비어 있으므로 **프로토타입이 이미 이 사고를 재현하고 있다.**

→ 반영: §2.1 「본문이 특약에 넘긴 자리」 + §7.2 접기 예외 + M2 완료 기준

### 1.2 실물에 공란이 남아 있다 ✔ 확인

`연 [ ]%`(제22조③) · `매월 ______원`(제25조②) · `년 월 일`(제4조·서명일) ·
서명란의 시공사/우선수익자 미기재.

→ 반영: §8.4(1) 잔존 공란 스캐너, M1

### 1.3 한 계약서 안에서 '수익자'의 범위가 세 번 달라진다 ✔ 확인

```
제2조3호    "우선수익자를 포함한다"
제29조③1호  "우선수익자는 포함되지 아니하며"
제29조④    "이 항에서 우선수익자를 포함한다"
```

법률문서에서 이건 **오류가 아니라 의도된 국소 재정의**다. 그래서 "불일치"로 판정하면 안 되고
목록만 제시한다.

→ 반영: §8.4(3), 판정 없이 목록만

### 1.4 별첨이 CDM에 없다 ✔ 구조 확인 (세 관점 모두 지적)

실물은 본문 35조 + 별첨 5종이고, **별첨5가 모드 E의 우측 전체**다. 지금 CDM은 조의 평평한
목록이라 "본문 vs 별첨5"라고 말할 수조차 없다. 별첨 안의 조 번호가 본문과 겹치므로
(본문 제1조 / 특약 제1조) 이건 필드 하나 추가가 아니라 **키가 바뀌는 변경**이다.

→ 반영: §4.1, **M0** (뒤로 미루면 M3.5에서 스키마가 깨진다)

## 2. 세 관점이 독립적으로 같은 말을 한 것

한 관점만의 취향이 아니라는 뜻이므로 우선순위를 올렸다.

| 지적 | 반영 위치 |
|---|---|
| 별첨/annex가 CDM에 없다 | §4.1 · M0 |
| 「누구에게」 없는 유불리 판정은 작성자 입장이 기본값이 된다 | §8.3 |
| 잔존 공란 스캐너 | §8.4(1) |
| 상호참조 무결성(조 번호가 밀려도 본문 속 인용 숫자는 안 따라간다) | §8.4(2) |
| 집합(목록) 비교 — 어긋나는 건 숫자가 아니라 예외사유의 개수다 | §2.2 |
| 부작위 탐지 — 있어야 할 조항이 조용히 빠진 것 | §2.2 `존재필수` |
| 모드 F를 앞당겨라 | **부분 수용** — §10 참조 |

**모드 F는 통째로 당기지 않았다.** F의 값은 `cross-check.yaml` 항목 목록에서 나오는데
그 목록이 아직 없다. 대신 **항목 목록을 요구하지 않는 부분만 떼어 M1로 옮겼다**
(§8.4의 셋 + 위임 미이행). 이들은 문서 한 건으로 동작한다.

## 3. 의견이 갈린 지점

### 3.1 수탁자 책임준공이 본문에 없는 것 — `불일치`인가 `미확인`인가

- **대주 관점**: 관리형 토지신탁인데 본문에 수탁자 책임준공이 없다 → 대출약정서가 전제하는
  책준과 어긋나므로 **불일치**
- **신탁사 관점**: 책준형 관리형토지신탁이 따로 존재하고, 수탁자 책준은 보통
  **특약·확약서에 들어간다.** 본문에 없다는 사실만으로 불일치라 하면 오탐이다 → **미확인**

**신탁사 쪽을 채택했다.** 근거는 도메인 지식이 아니라 도구 설계 원칙이다 — §8.3의
"틀린 판정보다 판정 없음이 낫다"와 같은 이유로, **못 본 것과 어긋난 것을 같은 색으로
칠하면 도구가 거짓 안심을 준다.**

그래서 판정을 4상태(`일치 | 불일치 | 누락 | 미확인`)로 하고, 룰에
`기재_예상_문서`(여기 없으면 누락)와 `참조_문서`(있으면 읽고 없어도 누락 아님)를 나눴다.

**단, 어느 쪽이 실무 관행인지는 확인이 필요하다** → §13.1-2

### 3.2 기준선을 무엇으로 둘 것인가

- **사내 표준특약을 기준선으로** (신탁사 관점, 모드 B의 확장)
- **대주 승인조건·텀시트를 기준선으로** (대주 관점)

맞붙여 보니 **경쟁하는 안이 아니라 서로 다른 축**이었다. 전자는 문서↔문서 비교(정렬 엔진),
후자는 조건표↔문서 대조(항목 추출 엔진)다. `baselines/` 레지스트리에 `type: document | schedule`
을 두고 각각 다른 엔진으로 보내면 둘 다 된다. 지금 초안에 넣기에는 이르므로 기록만 남긴다.

### 3.3 `내_입장` 설정을 둘 것인가

시행사 관점에서 나온 지적이 날카로웠다 — "입장 설정은 **세 층 중 한 층만** 지킨다."

```
1층  판정의 방향 (유리/불리)      ← §8.3이 다루던 층
2층  점검 항목의 선정              ← 우리가 넣은 항목만 검사한다
3층  애초에 무엇을 문제로 볼 것인가  ← 룰을 쓰는 사람의 세계관
```

**"없는 점검 항목은 뒤집을 게 없다."** 입장 전환 기능은 1층만 뒤집고 2·3층은 그대로다.

이 지적을 완전히 해소하지는 못했다. 대신 최소한 **`내_입장`이 필터로만 작동하고 탐지 결과를
줄이지 못하도록** 못을 박았다(§8.3). 입장을 바꿔도 항목 수는 변하지 않는다.

## 4. 반영하지 않은 것

| 의견 | 왜 안 넣었나 |
|---|---|
| 사업수지(분양가·공사비·금융비용) 연동 시뮬레이션 | 계약서 대조 도구의 범위를 벗어난다. 다른 도구다 |
| 요구사항 반영 추적(우리가 낸 수정요구가 다음 회차에 반영됐는지) | 타임머신(§7.3) + 대비표로 거의 보인다. 별 기능으로 만들 만한지 불확실 |
| 구체적 대안 조문 초안(면책범위·비용부담·해지제한 등) | 문구 라이브러리(모드 D)의 재료지, 설계 문서에 넣을 것이 아니다. 실물 확보 후 재검토 |
| 유형별 룰셋 YAML 초안 | 실물 없이 쓰면 지어낸 관행이 코드에 박힌다. §13.1이 채워진 뒤에 쓴다 |

## 5. 절차상 한계 (남겨둠)

- **대출약정 관점의 2차 교차검토가 완료되지 않았다** (호출 한도). §3.1·3.2의 반박을
  대주 쪽에서 다시 받지 못한 상태에서 신탁사 쪽 논거를 채택했다. 3.1은 도구 설계 원칙으로
  정당화되므로 뒤집힐 여지가 적지만, **실무 확인(§13.1-2) 전까지는 잠정이다.**
- 세 관점 모두 **실물 특약·승계계약서·대출약정서를 보지 못한 상태**에서 낸 의견이다.
  일반론으로서 맞더라도 이 회사의 문서에 맞는지는 별개다.
- 그래서 **검증된 것만 초안에 넣고, 나머지는 §13.1 목록으로 내렸다.** 이 문서에서 가장
  실용적인 산출물은 결론이 아니라 **그 확인 목록**이다.
